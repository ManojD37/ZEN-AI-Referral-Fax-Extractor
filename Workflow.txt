=============================================================================
        MEDICAL REFERRAL FAX EXTRACTOR - WORKFLOW DOCUMENTATION
=============================================================================

OVERVIEW
--------
This document explains how files are processed and how each code component 
works in the ZEN-AI Medical Referral Fax Extractor application.


=============================================================================
                          FILE PROCESSING FLOW
=============================================================================

STEP 1: USER UPLOADS FILE
-------------------------
Frontend: UploadPage.jsx

  User drops/selects file → validation (extension + size) → upload to backend

  - Allowed extensions: .pdf, .jpg, .jpeg, .png, .txt, .docx
  - Max file size: 50MB
  - Progress tracking via axios callbacks


STEP 2: BACKEND RECEIVES FILE
-----------------------------
Backend: main.py → POST /upload endpoint

  1. Validate file extension
  2. Validate file size (max 50MB)
  3. Route to text_extractor.py for content extraction


STEP 3: CONTENT EXTRACTION
--------------------------
Backend: text_extractor.py

  File Type    | Processing Method          | Output
  -------------|----------------------------|---------------------------
  PDF          | pdf_to_images_base64()     | List of base64 images
  JPG/PNG      | image_to_base64()          | Single base64 image
  TXT          | extract_text_from_txt()    | Raw text string
  DOCX         | extract_text_from_docx()   | Raw text string

  Visual formats (PDF, images) → converted to base64 for Vision API
  Text formats (TXT, DOCX) → extracted as raw text for LLM


STEP 4: AI EXTRACTION
---------------------
Backend: gpt_client.py

  PATH A: Images (PDF, JPG, PNG)
  - Uses GPT-4o Vision API
  - All pages/images sent in single request
  - max_tokens: 2000
  - temperature: 0.0 (deterministic)

  PATH B: Text (TXT, DOCX)
  - Uses GPT-4o Chat Completion
  - Text truncated to 8000 chars (cost optimization)
  - max_tokens: 2000
  - temperature: 0.0


STEP 5: CLASSIFICATION (Text Only)
----------------------------------
Backend: classifier.py

  For text documents, determines if it's a referral:
  
  Keywords Scored:
  - Strong keywords (referral, referring): 10 points each
  - Pattern matches: 8 points each
  - Medical keywords: 2 points each
  - Admin keywords: 1 point each
  
  Classification Result:
  - is_referral = strong_count >= 1 AND score >= 10
  - confidence = score / 50 (capped at 1.0)


STEP 6: SCHEMA VALIDATION
-------------------------
Backend: schemas.py

  Pydantic models validate the extracted data:
  
  ReferralExtraction:
    - document_meta (title, date, pages)
    - referral (to/from facility, contacts)
    - patient (name, DOB, gender, phone, address)
    - diagnoses (primary, other)
    - treatments
    - reason_for_referral


STEP 7: STORAGE
---------------
Backend: blob_storage.py

  Results saved to Azure Blob Storage:
  - extraction_id: UUID
  - filename: original filename
  - timestamp: ISO format
  - extracted_data: validated extraction


STEP 8: RESPONSE TO FRONTEND
----------------------------
  {
    "extraction_id": "uuid...",
    "classification": {...},
    "text_stats": {...},
    "extracted": {...}
  }


STEP 9: DISPLAY RESULTS
-----------------------
Frontend: OutputPage.jsx

  - Displays extracted data in categorized cards
  - Editable fields for manual corrections
  - Download as JSON button
  - Classification banner with confidence score

=============================================================================
                            COST OPTIMIZATION
=============================================================================

1. Model: gpt-4o-mini (most cost-effective with quality)
2. Temperature: 0.0 (no randomness = fewer tokens)
3. max_tokens: 2000 (reasonable limit)
4. Text truncation: 8000 chars (prevents token overflow)
5. Single API call per document (batched pages)
